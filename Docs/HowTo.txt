TÂCHE 41 : clearCcCookie — SecurityError sur about:blank (24/05/2026)
================================================================================
page.evaluate() pour manipuler document.cookie échoue avec SecurityError si la page
est sur about:blank (contexte fresh depuis storageState au début d'un test).
Fix : naviguer vers l'URL cible d'abord, puis manipuler le cookie.

  async function clearCcCookie(page, url) {
    if (!page.url().includes('staging-geo.onclusive.com')) {
      await page.goto(url, { waitUntil: 'load', timeout: 30000 });
      await page.waitForTimeout(1000);
    }
    await page.evaluate(() => { /* delete cookie */ });
    await page.goto(url, { waitUntil: 'load', timeout: 30000 });
  }

TÂCHE 2 : Extraction des screens Figma
--------------------------------------------------------------------------------

URL Figma utilisée :
  https://www.figma.com/design/xctSRqtM653zRS7QY3KMm0/Measure---GEO-Module

Méthodologie :

1. Lire le FIGMA_TOKEN depuis .env (format : figd_xxxxxxxxxxxxxxxxxxxx)

2. Extraire le file_id depuis l'URL Figma :
   URL : https://www.figma.com/design/{file_id}/{file_name}?node-id=...

3. Récupérer la structure du fichier via l'API :
   GET https://api.figma.com/v1/files/{file_id}?depth=3
   Headers: X-Figma-Token: {FIGMA_TOKEN}

4. Filtrer les frames :
   - Garder uniquement les frames de type FRAME
   - Exclure les frames de type N0TE (annotations uniquement, pas des écrans UI)

5. Exporter les images par batches de 3 maximum (pour éviter les timeouts) :
   GET https://api.figma.com/v1/images/{file_id}?ids={id1},{id2},{id3}&format=png&scale=2
   Headers: X-Figma-Token: {FIGMA_TOKEN}

6. Télécharger et sauvegarder chaque PNG dans figmaScreens/{section}/

7. Nommage des dossiers et fichiers :
   - Préfixe numérique (01_, 02_...) pour maintenir l'ordre
   - Remplacer les espaces par _ dans les noms de fichiers

TÂCHE 21 : Bonnes pratiques E2E — Référence complète (à appliquer sur tout nouveau spec)
--------------------------------------------------------------------------------

Ces pratiques ont été établies suite au développement de kpi-cards-category-analysis.spec.js
et permettent de réduire les itérations de debug de 4 à 2 en moyenne.

── 1. INSPECTION DOM AVANT LE SPEC ────────────────────────────────────────────

Toujours inspecter la page via Playwright headless AVANT d'écrire une assertion.
Script type (node --input-type=module) :

  import { chromium } from '@playwright/test';
  const browser = await chromium.launch({ headless: true });
  const ctx = await browser.newContext({ storageState: '.claude/Data/processed/auth/storageState.json' });
  const page = await ctx.newPage();
  await page.goto(URL);
  await page.waitForLoadState('networkidle');
  const result = await page.evaluate(() => {
    // 1. Chercher les data-testid disponibles
    const testids = [...new Set([...document.querySelectorAll('[data-testid]')].map(e => e.getAttribute('data-testid')))];
    // 2. Chercher l'élément par son texte visible
    const el = [...document.querySelectorAll('*')].find(e => e.textContent.trim() === 'Mon texte');
    return { testids, elHtml: el?.outerHTML?.slice(0,300) };
  });
  console.log(JSON.stringify(result, null, 2));
  await browser.close();

Ordre de priorité des sélecteurs (OBLIGATOIRE) :
  1. data-testid          → [data-testid="mon-element"]
  2. aria-label           → div[aria-label^="Share of Voice"]  ← KPI cards
  3. role ARIA            → button[role="switch"]:not([disabled])
  4. class stable         → p.font-medium, span[class*="text-emerald-600"]
  5. getByText()          → uniquement pour contenu dynamique (données métier, CSV)

Pièges courants découverts en inspection :
  - LLM dropdown : options = button[role="switch"], pas role="option"
  - LLM switches disabled : :not([disabled]) obligatoire pour filtrer les inactifs
  - CSS text-overflow:ellipsis : les spans peuvent avoir getBoundingClientRect() ≈ 0
    → annoter le bouton parent (btn.getBoundingClientRect()) pas le span
  - Skeleton loader : [class*="animate-pulse"], pas [class*="skeleton"]
  - AI Perception Summary : ul[role="list"] li[role="listitem"] pour les bullets

── 2. e2e-helpers.js — MODULE PARTAGÉ (OBLIGATOIRE) ───────────────────────────

Fichier : .claude/Data/raw/playwright/e2e-helpers.js

Import en tête de chaque spec :
  const H = require('./e2e-helpers');
  const SCREENSHOTS_DIR = path.resolve(__dirname, '../../output/reports/screenshots-mon-spec');
  H.ensureDir(SCREENSHOTS_DIR);
  const shot   = H.makeShot(SCREENSHOTS_DIR);    // capture viewport
  const shotAt = H.makeShotAt(SCREENSHOTS_DIR);  // scroll + capture
  H.registerAfterEach(SCREENSHOTS_DIR);           // hook annotation rouge

API exportée :
  H.makeShot(dir)                          → shot(page, name) — viewport tel quel
  H.makeShotAt(dir)                        → shotAt(page, locator, name) — scroll puis capture
  H.registerAfterEach(dir)                 → hook afterEach complet (overlay rouge + backfill)
  H.assertLLMButtons(page, dir, tcId, step)→ logos visibles + labels cachés (compact mode)
  H.switchAllLLMs(page)                    → bascule 5 LLMs, vérifie panel visible
  H.ensureDir(dir)                         → crée le dossier screenshots
  H.goto(page, url)                        → navigate + networkidle
  H.LLM_ALTS, H.LLM_LABELS                → constantes GEO LLM

Ne JAMAIS dupliquer le bloc afterEach inline dans un spec — utiliser H.registerAfterEach().

── 3. SHOTÁT — SCREENSHOTS CIBLÉS (OBLIGATOIRE) ───────────────────────────────

Règle : chaque screenshot doit montrer la section exacte vérifiée par le step,
pas le haut de la page (résultat de shot() sans scroll).

Utiliser shotAt() pour tous les steps d'assertion portant sur une section précise :

  // ✅ Correct — scroll vers les KPI cards avant la capture
  await shotAt(page, page.locator('div[aria-label^="Share of Voice"]').first(), 'TC002_step3_then');

  // ✅ Correct — scroll vers l'AI Perception Summary
  await shotAt(page, page.locator('h4').filter({ hasText: 'AI Perception Summary' }).first(), 'TC007_step3_then');

  // ✅ Correct — skeleton visible pendant le refetch
  await shotAt(page, page.locator('[class*="animate-pulse"]').first(), 'TC005_step2_when');

  // ❌ Interdit pour steps d'assertion sur section spécifique
  await shot(page, 'TC002_step3_then');  // montre le haut de la page, pas les KPI cards

shot() reste acceptable pour :
  - step1_given (état initial — haut de page acceptable)
  - Captures après navigation (page entière vient de charger)

── 4. DEBUG PAR TC ISOLÉ (OBLIGATOIRE) ────────────────────────────────────────

Ne jamais relancer la suite complète pendant le debug d'un seul TC.
Utiliser le flag --grep :

  SPEC_NAME=mon-spec USE_AUTH=true npx playwright test mon-spec.spec.js --grep "TC003"

Lancer la suite complète uniquement en validation finale.

── 5. RÈGLE SKIP (OBLIGATOIRE) ────────────────────────────────────────────────

Ne jamais décider seul de sauter un TC sans en informer l'utilisateur.
Si une condition n'est pas reproductible sur staging :
  1. Documenter dans le test.skip() pourquoi la condition manque
  2. Signaler à l'utilisateur avant d'ajouter le skip
  3. Proposer une alternative (autre dataset, autre URL)

Exemple conforme :
  test.skip('KPI-TC006 [SKIP] N/A state — no reproducible condition on staging', async ({ page }) => {
    // Skipped: aucune catégorie sur staging ne produit N/A pour un KPI.
    // Condition requise : catégorie sans réponses compétitives ou de visibilité.
    // Signalé à l'utilisateur le 2026-05-06.
  });

TÂCHE 25 : Ordre d'exécution — contrainte du timestamp guard (build-e2e-suite-report.js)
--------------------------------------------------------------------------------

build-e2e-suite-report.js contient un timestamp guard :
si le raw JSON d'un spec individuel est PLUS ANCIEN que le raw de l'e2e-suite,
ce spec est ignoré lors du refresh (ses résultats précédents sont conservés).

CONSÉQUENCE :
  - Le run e2e-suite doit être lancé EN PREMIER
  - Le run individuel (ex: create-default-analysis) doit être lancé EN DERNIER

  ORDRE CORRECT :
    1. npx playwright test --project=e2e-suite
       → produit test-results-e2e-suite-raw.json (timestamp T1)
    2. npx playwright test create-default-analysis.spec.js
       → produit son raw à T2 > T1 → guard laisse passer → résultat intégré

  ORDRE INCORRECT (résultat ignoré) :
    1. npx playwright test create-default-analysis.spec.js (raw T1)
    2. npx playwright test --project=e2e-suite (raw T2 > T1 → guard skip le spec individuel)

Si l'ordre est inversé, l'ancien statut du TC est conservé à tort dans le rapport.

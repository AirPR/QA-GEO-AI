# Skill : Requirements Analysis and Crossing

## Trigger
/analyze-req

## Prerequisites
- .claude/Data/processed/requirements/functional_requirements.json must exist (generated by /read-prd)
- .claude/Data/processed/requirements/acceptance_criteria_mapped.json must exist (generated by /fetch-jira)
- .claude/Data/raw/jira/epics_raw.json must exist (generated by /fetch-jira)

## 3 Analysis Sources (MANDATORY)

| Source | File | Content |
|--------|------|---------|
| **PRD** | functional_requirements.json | FRs, business flows, constraints |
| **Jira Stories** | acceptance_criteria_mapped.json | Functional ACs from stories (technical bullets filtered) |
| **Jira Epics** | epics_raw.json | Scope overviews, epic-level ACs, cross-story E2E flows |

## Execution Steps

1. Load the 3 source files
2. Perform the 3-level crossing:
   a. **Epic → FRs**: Associate each Epic (via its overview and embedded stories) with PRD FRs
   b. **Story AC → FRs**: Associate each functional AC with one or more PRD FRs
   c. **Gaps**: Identify PRD FRs not covered by any Epic or story
   d. **Out of scope**: Identify stories with no match in the PRD
3. Analyse Epic descriptions:
   - Extract cross-cutting constraints (atomicity, on-demand, performance)
   - Identify implicit E2E flows in overviews (not detailed in stories)
   - Identify Epics without formal ACs (risk for testing)
4. Detect ambiguities:
   - Criteria too vague ("the system must be fast")
   - Contradictory requirements between PRD, Epics and stories
   - Unspecified boundary cases
   - Different behaviours between Wizard and Manage Scope for the same feature
5. Produce an analysis report displayed in the terminal
6. Save to coverage_analysis.json
7. Ask for confirmation before proceeding to /gen-tests

## Expected Output
- 3-level coverage table: FRs ↔ Epics ↔ Stories
- List of identified gaps (uncovered FRs)
- List of cross-cutting constraints extracted from Epics
- List of ambiguities to clarify
- Recommendation: ready for generation / clarification required first
